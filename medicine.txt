CAMERA-BASED MEDICINE CONFIRMATION:

I want the user to be able to take a LIVE picture of the medicine when a reminder fires.

The intended workflow is:

1. A scheduled medicine reminder becomes due.
2. The application starts a persistent reminder/alarm.
3. The alarm should continue until the user completes the reminder confirmation flow.
4. The user opens the camera from the reminder screen.
5. The user takes a live photograph of the medicine.
6. The application performs a LOCAL visual consistency check against the medicine's previously configured/reference image.
7. The visual check should consider characteristics such as:
   - approximate color
   - approximate size
   - shape/form where technically feasible
8. If the visual characteristics are sufficiently consistent:
   - show "Visual match detected"
   - ask the user to explicitly confirm that they have taken the medicine
   - only after the user's confirmation should the reminder be marked as completed and the alarm stop.
9. If the visual check does not match sufficiently:
   - do NOT mark the medicine as taken
   - keep the reminder active
   - tell the user that the image could not be visually matched
   - allow the user to retake the photo.
10. The application must never claim that the camera has medically identified or authenticated a medicine.
11. Clearly communicate that visual matching is only a convenience/consistency check and cannot guarantee medicine identity or safety.
12. Never recommend that the user take a medicine based on the visual model.
13. Never infer dosage from the photograph.
14. Never infer whether a medicine is safe for the user.
15. Never infer medical information from the image.

REFERENCE MEDICINE IMAGE:

When adding a medicine, allow the user to optionally capture or select a reference photograph.

The reference should be associated with that medicine.

When the reminder later fires, compare the newly captured image against the stored reference image.

The comparison should be designed as a visual similarity check rather than medicine identification.

IMPORTANT PRIVACY REQUIREMENT:

Prefer LOCAL image processing.

Do not upload medicine photographs to a cloud AI service unless I explicitly approve that architecture first.

The application should explain where medicine images are stored.

REMINDER BEHAVIOR:

The reminder should have a persistent alarm state.

Example:

    ↓
Persistent alarm
    ↓
"Take your medicine"
    ↓
Open camera
    ↓
Capture live image
    ↓
Visual consistency check
    ↓
If insufficient match
    → Alarm continues
    → Retake photo
    ↓
If sufficient visual match
    ↓
User explicitly confirms "I took this medicine"
    ↓
Mark as Taken
    ↓
Stop alarm

However, make it clear that these actions have different meanings from "Taken".

Do not make assumptions about what medical action the user should take.
